# Libft

Libft is a C library project from the 42 curriculum. Its goal is to rebuild a collection of useful functions normally provided by the C standard library, then extend that collection with string utilities, output helpers, and linked-list operations. Implementing these functions helps develop a practical understanding of pointers, memory management, string handling, function pointers, and data structures.

## Description

The goal of Libft is to build a reusable C library from the ground up. The project reinforces the fundamentals needed to work confidently with C, including pointers, byte-level memory operations, null-terminated strings, dynamic allocation, function pointers, file descriptors, and linked data structures.

The library provides three groups of functions defined by the project subject:

1. **Libc reimplementations** prefixed with `ft_`, covering character classification, string operations, memory operations, and numeric conversion.
2. **Additional utilities** for creating and transforming strings, splitting text, converting integers to strings, applying callbacks, and writing values to file descriptors.
3. **Singly linked-list operations** based on the public `t_list` structure declared in `libft.h`.

The objective is not only to expose convenient helpers, but also to understand the contracts behind common C routines: who owns allocated memory, how buffer sizes are interpreted, how byte sequences differ from strings, and how pointers and callbacks can be used to build reusable interfaces.

## Library Overview

- **Library name:** `libft.a`
- **Public header:** `libft.h`
- **Language:** C
- **Build tool:** `make`
- **Compiler:** `cc`
- **Compiler flags:** `-Wall -Wextra -Werror`
- **Archive tool:** `ar`
- **Link type:** static library

The public function prototypes and the `t_list` definition are declared in `libft.h`. The Makefile lists the corresponding `ft_*.c` translation units and builds their object files into `libft.a`.

The function descriptions below summarize the Libft subject's expected contracts and the prototypes in `libft.h`. They do not promise extra behavior for invalid pointers or other inputs outside a function's documented contract.

## Instructions

### Prerequisites

Use a Unix-like C development environment with:

- `cc`, compatible with the compiler command required by the subject;
- `make` to run the build rules;
- `ar` to create the static archive;
- the standard C library and system headers used by the project, including `<stdlib.h>` and `<unistd.h>`.

The project is built with `-Wall -Wextra -Werror`. These options enable common warnings and treat warnings as errors.

### Build the Library

Run these commands from the repository root:

```sh
make
```

The default target builds `libft.a`. The Makefile compiles the listed `.c` files into object files and archives them using `ar -crs`.

To remove generated object files:

```sh
make clean
```

To remove both object files and the library archive:

```sh
make fclean
```

To perform a clean rebuild:

```sh
make re
```

### Makefile Targets

| Target | Purpose |
|---|---|
| `all` | Builds `libft.a`; this is also the default target. |
| `libft.a` | Compiles the required object files and creates the static archive. |
| `clean` | Removes the object files listed by the Makefile. |
| `fclean` | Runs `clean` and removes `libft.a`. |
| `re` | Runs `fclean`, then builds the library again. |

The Makefile does not define a `bonus` or `test` target. The linked-list functions are included in the listed build sources rather than exposed through a separate Makefile target.

### Use Libft in a C Program

Include `libft.h` in the program that uses the library. For example, create a `main.c` file in the repository root:

```c
#include "libft.h"
#include <stdio.h>

int main(void)
{
    const char *message = "Hello, Libft!";

    printf("Length: %zu\n", ft_strlen(message));
    return (0);
}
```

Build the library first, then compile and link the program:

```sh
make
cc -Wall -Wextra -Werror -I. main.c -L. -lft -o example
./example
```

- `-I.` tells the compiler to look for `libft.h` in the current directory.
- `-L.` adds the current directory to the library search path.
- `-lft` links against `libft.a` (the `lib` prefix and `.a` suffix are omitted).
- `-o example` names the resulting executable `example`.

The example prints the length of the string. When linking a static library, put the library after the source files or object files that use its symbols.

## Detailed Library Reference

### Part 1: Libc Functions

These functions reimplement selected character, string, memory, and conversion routines under the `ft_` prefix. Their intended behavior follows the corresponding function contracts in the Libft subject.

#### Character Classification and Conversion

| Function and prototype | Purpose and behavior | Return value |
|---|---|---|
| `int ft_isalpha(int c)` | Checks whether `c` is an alphabetic character. | `1` when it matches; otherwise `0`, as required by the subject. |
| `int ft_isdigit(int c)` | Checks whether `c` is a decimal digit (`0`–`9`). | `1` when it matches; otherwise `0`. |
| `int ft_isalnum(int c)` | Checks whether `c` is alphabetic or a decimal digit. | `1` when it matches; otherwise `0`. |
| `int ft_isascii(int c)` | Checks whether `c` is in the ASCII range (`0`–`127`). | `1` when it matches; otherwise `0`. |
| `int ft_isprint(int c)` | Checks whether `c` is printable, including the space character. | `1` when it matches; otherwise `0`. |
| `int ft_toupper(int c)` | Converts a lowercase alphabetic character to uppercase; other valid character values remain unchanged. | The converted character value. |
| `int ft_tolower(int c)` | Converts an uppercase alphabetic character to lowercase; other valid character values remain unchanged. | The converted character value. |

#### String Operations

| Function and prototype | Purpose and important behavior | Return value |
|---|---|---|
| `size_t ft_strlen(const char *str)` | Counts bytes before the terminating `\0`; the terminator is not included. | String length. |
| `size_t ft_strlcpy(char *dst, const char *src, size_t size)` | Copies a string into a size-limited destination. If `size` is greater than zero, the destination is terminated with `\0`; at most `size - 1` source bytes are copied. | Length of `src`, allowing callers to detect truncation. |
| `size_t ft_strlcat(char *dst, const char *src, size_t size)` | Appends `src` to a size-limited destination when the destination is terminated within the first `size` bytes. The size includes space for the final `\0`. If no terminator is found within those `size` bytes, no append occurs. | The length it tried to create: the destination length within `size` plus the source length. If the destination is not terminated within `size`, this is `size + strlen(src)`. |
| `char *ft_strchr(const char *s, int c)` | Finds the first occurrence of `c` in `s`. The terminating `\0` is also searchable. | Pointer to the match, or `NULL` if no match exists. |
| `char *ft_strrchr(const char *s, int c)` | Finds the last occurrence of `c` in `s`. The terminating `\0` is also searchable. | Pointer to the last match, or `NULL` if no match exists. |
| `int ft_strncmp(const char *s1, const char *s2, size_t n)` | Compares at most the first `n` bytes of two strings, stopping at a difference or a terminator. | Negative, zero, or positive according to the comparison. |
| `char *ft_strnstr(const char *big, const char *little, size_t len)` | Searches for `little` within the first `len` bytes of `big`. An empty `little` matches at the start of `big`. | Pointer to the first match, or `NULL` if no match is found in the permitted range. |
| `char *ft_strdup(const char *s)` | Allocates storage for and copies the string, including its terminating `\0`. | Pointer to the new string, or `NULL` if allocation fails. The caller must free the returned string. |

For `ft_strlcpy` and `ft_strlcat`, `size` is the total destination-buffer capacity, not simply the number of non-terminating characters available. A caller must still provide valid, suitably sized buffers and null-terminated source strings where required.

#### Memory Operations

| Function and prototype | Purpose and important behavior | Return value |
|---|---|---|
| `void *ft_memset(void *s, int c, size_t n)` | Writes the byte value obtained from `c` to each of the first `n` bytes of the memory region. | The original pointer `s`. |
| `void ft_bzero(void *s, size_t n)` | Sets the first `n` bytes of the memory region to zero. | None. |
| `void *ft_memcpy(void *dest, const void *src, size_t n)` | Copies `n` bytes from source to destination. The memory regions must not overlap. | The original pointer `dest`. |
| `void *ft_memmove(void *dest, const void *src, size_t n)` | Copies `n` bytes and supports overlapping source and destination regions. | The original pointer `dest`. |
| `void *ft_memchr(const void *s, int c, size_t n)` | Searches the first `n` bytes for the byte value obtained from `c`. Unlike string searches, it does not stop at a `\0` byte. | Pointer to the first match, or `NULL` if not found. |
| `int ft_memcmp(const void *s1, const void *s2, size_t n)` | Compares the first `n` bytes as unsigned byte values; it can compare buffers containing zero bytes. | Negative, zero, or positive according to the first differing byte. |
| `void *ft_calloc(size_t nmemb, size_t size)` | Allocates storage for `nmemb` elements of `size` bytes each and initializes the allocated bytes to zero. The subject specifies that a zero dimension must yield a pointer value that can safely be passed to `free`. | Pointer to the allocated memory, or `NULL` if allocation fails. |

Use string functions for null-terminated text and memory functions for byte sequences of known length. `ft_memcpy` is not appropriate for overlapping regions; use `ft_memmove` for that case. Dynamically allocated memory must be released when it is no longer needed.

#### Numeric Conversion

| Function and prototype | Purpose and important behavior | Return value |
|---|---|---|
| `int ft_atoi(const char *nptr)` | Converts the initial decimal integer portion of a string, allowing leading whitespace and an optional sign. Conversion stops at the first character that is not part of the number. | The converted `int`. The interface does not provide a separate error indicator, so callers should not use out-of-range input as an overflow-detection mechanism. |

### Part 2: Additional Functions

These utilities extend the basic string and memory operations. Functions that allocate a new string return memory owned by the caller.

#### String Creation and Transformation

| Function and prototype | Purpose and important behavior | Return value |
|---|---|---|
| `char *ft_substr(char const *s, unsigned int start, size_t len)` | Creates a substring beginning at index `start`, copying no more than `len` characters. If `start` is at or beyond the string's end, the resulting substring is empty. | Newly allocated string, or `NULL` if allocation fails. |
| `char *ft_strjoin(char const *s1, char const *s2)` | Creates a new string containing `s1` followed by `s2`. | Newly allocated concatenated string, or `NULL` if allocation fails. |
| `char *ft_strtrim(char const *s1, char const *set)` | Creates a copy of `s1` with any characters present in `set` removed from the beginning and end. Characters in the middle are preserved. | Newly allocated trimmed string, or `NULL` if allocation fails. |
| `char **ft_split(char const *s, char c)` | Splits `s` at delimiter `c`. The returned array is terminated by a `NULL` pointer, and each resulting string is allocated separately. | Array of strings, or `NULL` if an allocation fails. Free each string, then the array. |
| `char *ft_itoa(int n)` | Converts an integer, including a negative value, into its decimal string representation. | Newly allocated string, or `NULL` if allocation fails. |

#### Callback-Based String Iteration

| Function and prototype | Purpose and important behavior | Return value |
|---|---|---|
| `char *ft_strmapi(char const *s, char (*f)(unsigned int, char))` | Calls `f` for each character, passing its index and character value, and stores the returned characters in a newly allocated string. | Newly allocated transformed string, or `NULL` if allocation fails. |
| `void ft_striteri(char *s, void (*f)(unsigned int, char *))` | Calls `f` for each character, passing its index and the address of that character so the callback can modify it in place. | None. The original string is modified through the callback. |

The callback supplied to either function must be valid for every invocation. `ft_strmapi` returns a new allocation; `ft_striteri` operates on the original writable string.

#### Output to File Descriptors

| Function and prototype | Purpose and important behavior | Return value |
|---|---|---|
| `void ft_putchar_fd(char c, int fd)` | Writes one character to file descriptor `fd`. | None. |
| `void ft_putstr_fd(char *s, int fd)` | Writes the string `s` to file descriptor `fd` without adding a newline. | None. |
| `void ft_putendl_fd(char *s, int fd)` | Writes `s` followed by a newline to file descriptor `fd`. | None. |
| `void ft_putnbr_fd(int n, int fd)` | Writes the decimal representation of integer `n` to file descriptor `fd`. | None. |

A file descriptor identifies the destination for output. Common examples are `1` for standard output and `2` for standard error. These functions return `void`, so callers cannot obtain a write error status from their public interface.

### Part 3: Linked Lists

Libft defines a singly linked-list node in `libft.h`:

```c
typedef struct s_list
{
    void            *content;
    struct s_list   *next;
}   t_list;
```

- `content` points to the data stored in the node. Its `void *` type allows the list to hold different data types.
- `next` points to the next node, or is `NULL` for the last node.

The list functions provide common operations for creating, traversing, transforming, and freeing nodes.

| Function and prototype | Purpose and important behavior | Return value |
|---|---|---|
| `t_list *ft_lstnew(void *content)` | Allocates a node, stores `content` in it, and initializes `next` to `NULL`. The content itself is not described as being copied. | Pointer to the new node, or `NULL` if allocation fails. |
| `void ft_lstadd_front(t_list **lst, t_list *new)` | Adds `new` before the current first node and updates the list head. | None. |
| `void ft_lstadd_back(t_list **lst, t_list *new)` | Adds `new` after the current last node, making it the last node. | None. |
| `unsigned int ft_lstsize(t_list *lst)` | Counts the nodes in the list. | Number of nodes. |
| `t_list *ft_lstlast(t_list *lst)` | Traverses the list to find the final node. | Pointer to the last node; an empty list has no last node. |
| `void ft_lstdelone(t_list *lst, void (*del)(void *))` | Calls `del` on the node's content and frees the node itself. It does not free the following nodes. | None. |
| `void ft_lstclear(t_list **lst, void (*del)(void *))` | Deletes the nodes in the list, calls `del` for their content, and sets the list head to `NULL`. | None. |
| `void ft_lstiter(t_list *lst, void (*f)(void *))` | Calls `f` on the content of each node in sequence. | None. |
| `t_list *ft_lstmap(t_list *lst, void *(*f)(void *), void (*del)(void *))` | Applies `f` to each node's content and builds a separate list from the transformed content. `del` provides the content-cleanup callback used by the operation. | Pointer to the new list, or `NULL` if allocation fails. |

The list stores pointers; it does not inherently know how the pointed-to content was allocated. Choose a suitable `del` callback for the content type and ensure that nodes and their content are released exactly once. `ft_lstdelone` frees one node, while `ft_lstclear` is the operation for clearing a whole list.

## Memory Management and Safe Use

- **Check allocation results.** Functions that create strings, arrays, nodes, or other dynamic storage can fail and return `NULL` as specified by their contract.
- **Free returned allocations.** Release strings returned by functions such as `ft_strdup`, `ft_substr`, `ft_strjoin`, `ft_strtrim`, and `ft_itoa`. For `ft_split`, free every returned word before freeing the pointer array.
- **Respect buffer sizes.** The destination size passed to `ft_strlcpy` and `ft_strlcat` must describe the actual destination buffer capacity.
- **Avoid undefined memory access.** Supply valid pointers and sufficient storage for the operation. Do not use `ft_memcpy` with overlapping regions.
- **Manage list content deliberately.** Use a deletion callback that matches the way each node's `content` was created; freeing a pointer that was not dynamically allocated is invalid.
- **Do not assume extra `NULL` handling.** The prototypes and project subject define the public contract. Inputs outside that contract should not be assumed safe unless the corresponding implementation explicitly supports them.
